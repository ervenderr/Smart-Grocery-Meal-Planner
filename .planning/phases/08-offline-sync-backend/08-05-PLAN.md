## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> Idempotency-Key header | Untrusted string chosen by the client |
| middleware -> idempotency_keys | Stored response bodies replayed later |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-16 | Information disclosure | replay lookup | mitigate | Unique (user_id, key) scope; lookup always by authenticated req.user.id, so user B can never replay user A's stored response; tested |
| T-08-17 | Tampering | key reuse across routes/bodies | mitigate | requestHash covers method + route + canonical body; mismatch returns 422 |
| T-08-18 | Tampering | SQL in reservation | mitigate | Tagged $queryRaw only; grep gate forbids *Unsafe |
| T-08-19 | Denial of service | table growth / large bodies | mitigate | Key length 8..255 regex, 512 KB stored-body cap, 48 h TTL, daily prune, per-user rate limits |
| T-08-20 | Tampering | double apply under concurrency | mitigate | INSERT ON CONFLICT is the arbiter; in-flight duplicate 409; conditional takeOver for stale rows |
| T-08-21 | Information disclosure | logs | mitigate | Write failures log userId and route only; never key, body or tokens |
| T-08-22 | Tampering | crash between commit and completion write | accept | Single Railway replica, one-statement window; documented in middleware comment (research A3) |
</threat_model>
