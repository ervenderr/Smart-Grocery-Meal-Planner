  <behavior>
    - issueRefreshToken(userId) returns { refreshToken (43-char base64url), refreshExpiresAt = now + ttlDays, familyId }; DB row has tokenHash = sha256 hex of the raw token and no plaintext anywhere
    - rotateRefreshToken(raw) on an active token: old row revoked with reason 'rotated', new row in same family, returns { userId, refreshToken, refreshExpiresAt }
    - Rotating the same old token again within reuseGraceSeconds returns a new valid successor in the same family (no revocation)
    - Rotating an old token after the grace window: all rows of the family get revokedAt set with reason 'reuse'; throws 401 AppError code REFRESH_TOKEN_REUSED
    - Unknown token, expired token, token revoked for logout/password_change: 401 code REFRESH_TOKEN_INVALID (uniform message)
    - Inactive user (isActive false): family revoked with reason 'inactive', 401
    - Two concurrent rotations of the same active token (Promise.all) both succeed or one succeeds and the other is answered via the grace rule; never more than one active successor per call and never a family revocation
    - revokeFamilyByToken(raw, 'logout') revokes the family and is a no-op for unknown tokens; revokeAllForUser(userId, 'password_change') revokes all of that user's active rows only
  </behavior>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-23 | Spoofing | stolen refresh token replay | mitigate | Rotation on every use; reuse after 60 s grace revokes the whole family; 90 d absolute expiry |
| T-08-24 | Information disclosure | token storage | mitigate | Only sha256 hash stored; plaintext returned once; grep gate forbids logging raw/hash values |
| T-08-25 | Spoofing | brute force of /auth/refresh | mitigate | 256-bit CSPRNG tokens, zod regex/length check, refreshLimiter 30/15 min per IP, uniform 401 message |
| T-08-26 | Information disclosure | logout oracle | mitigate | Logout always 200 regardless of token validity |
| T-08-27 | Elevation of privilege | deactivated/deleted users | mitigate | Rotation checks user.isActive (family revoked 'inactive'); deleted users' rows removed by cascade + explicit delete (08-01) |
| T-08-28 | Spoofing | session after password change | mitigate | changePassword revokes all refresh rows (tested) |
| T-08-29 | Spoofing | grace window abuse | accept | 60 s bounded window, same family only; deliberate trade-off documented (research A2) |
</threat_model>
