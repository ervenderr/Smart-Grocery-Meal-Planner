<objective>
Make "Finish trip" safe for trips recorded offline: accept `occurredAt`, widen the receipt-date window to 14 days back / 1 day ahead, and run the bought-it pantry merge inside the same transaction as the finish.

Purpose: SYNC-05. Offline trips can be days old; today a crash between the finish commit and the separate merge transaction loses the merge. (Replay-safety of a retried finish comes from the idempotency middleware in plan 08-05, which adds the replay test.)
Output: New receipt-window util, refactored finish/merge services and controller, updated tests.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-09 | Tampering | occurredAt | mitigate | Strict ISO-8601 validation; server clamps to [now-14d, now], so a client cannot backdate beyond 14 days or future-date |
| T-08-10 | Tampering | receiptDate | mitigate | withinReceiptWindow rejects non-round-tripping dates and anything outside -14d/+1d with 400 |
| T-08-11 | Denial of service | finish tx holding list + pantry locks | mitigate | Fixed lock order (list then pantry), 15 s tx timeout, merge read capped at PANTRY_MERGE_READ_CAP |
| T-08-12 | Elevation of privilege | merge writes | mitigate | All pantry updates keep `where: { id, userId }`; list lock scoped to caller's userId |
</threat_model>
