    - before init: isReady() false, getAccess()/getRefresh() null
    - init() reads both keys once; second concurrent init() call returns the same promise (backend.get called exactly twice total)
    - init() with backend.get rejecting resolves { readFailed: true, snapshot: {access:null, refresh:null} }, logs message only (assert console.error args never contain the token string)
    - set({token:'A', refreshToken:'R'}) -> getAccess() === 'A' synchronously before the returned promise resolves; backend.set called with ('access','A') and ('refresh','R')
    - set({token:'B'}) keeps refresh 'R' and only writes 'access'
    - set() replaces the snapshot object (previous snapshot reference unchanged; immutability)
    - backend.set rejecting: set() resolves (does not throw), memory still updated, error logged without token
    - clear() -> both getters null synchronously; backend.remove called for both keys; a remove failure is logged and swallowed
    - flush() resolves after all pending write-through promises settle (order: set then clear leaves backend empty)
    native-boot (fake storage object + fake backend):
    - marker absent -> backend.remove('access') and ('refresh') called, marker set to an ISO timestamp, returns firstLaunch true
    - marker present -> backend.remove NOT called, firstLaunch false
    - always removes 'auth-token' and 'refresh-token' from storage
    - 'auth-storage' JSON with state.token is rewritten without token and isAuthenticated (user kept); invalid JSON is removed
    - storage undefined or throwing getItem -> still resolves, no throw

    - selectPersisted(state, false) deep-equals { user, token, isAuthenticated } (web unchanged)
