# Phase 10 — UI Design Contract

> Visual and interaction contract for the Capacitor iOS shell. Generated by gsd-ui-researcher (autonomous mode), verified by gsd-ui-checker.
> Scope: this phase adds NO new visual language. It makes the existing Kitcha UI behave natively inside WKWebView and adds a small number of platform-conditional surfaces. All tokens below are the existing Kitcha tokens (frontend/app/globals.css `@theme`, `components/ui/*`); nothing is re-specified except where native behavior needs a rule.
> Sources: 10-CONTEXT.md (decisions), research-v2/01-native-path.md (sections 8, 11), existing frontend scan.

## Spacing Scale

Existing Tailwind 4 default 4px grid is used. Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, gap between sheet action buttons |
| md | 16px | Default page/card padding (`p-4`), sheet horizontal padding |
| lg | 24px | Sheet section padding, permission-explainer vertical rhythm |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions (native-specific, all required):
- Touch targets: minimum 44px x 44px (existing `.touch-target`, Button `md`/`icon` = 44px, `lg` = 48px). No interactive control under 44px on native.
- Safe-area insets are added ON TOP of the scale, never rounded into it: `env(safe-area-inset-top|right|bottom|left)`.
- Bottom tab bar height 56px content + `env(safe-area-inset-bottom)`. Main scroll container already uses `pb-[calc(5rem+env(safe-area-inset-bottom))]`; keep it.
- Header: content height unchanged, with `padding-top: env(safe-area-inset-top)` (existing `.pt-safe`).

## Typography

Exactly 4 sizes and 2 weights, taken from the existing scale (tailwind `text-sm/base/xl/2xl`).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 | 1.5 |
| Label | 14px (`text-sm`) | 600 | 1.4 (20px) |
| Heading | 20px (`text-xl`) | 600 | 1.4 (28px) |
| Display | 24px (`text-2xl`) | 600 | 1.33 (32px) |

Rules:
- All text inputs 16px minimum (existing globals.css rule prevents iOS focus zoom). Keep it; do not lower under native.
- Secondary/helper text uses Label size at weight 400 is NOT allowed (would add a weight combo); use Body 16px at weight 400 in `text-gray-600` or Label 14px at 600.
- Respect iOS Dynamic Type: not supported in this phase (fixed px). Note as known limitation.
- `-webkit-touch-callout: none` and `user-select: none` on buttons, tab bar, chips, and list rows under native; keep text selectable in recipe instructions and inputs (`user-select: text`).

## Color

Existing Kitcha light theme (dark mode is forced off; keep it off, so the status bar is always dark-content).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9fafb` (gray-50) app canvas / `#ffffff` body | Page background (`bg-gray-50` shell), WebView background |
| Secondary (30%) | `#ffffff` with `border-gray-200` / `shadow-soft` | Cards, header, bottom tab bar, sheets |
| Accent (10%) | `#0ea5e9` (primary-500); pressed `#0369a1` (primary-700) | See reserved list |
| Destructive | `#ef4444` (red-500, Button `danger`) | Destructive actions only |

Accent reserved for: primary CTA buttons (e.g. "Turn on reminders", "Scan barcode"), active bottom-tab icon + label, focus ring, the scan viewfinder corner brackets, the on-state of `Switch`. Never for body links in legal text, icons at rest, or decorative fills.

Native color wiring (must match, otherwise white flashes at launch and overscroll):
- Capacitor `backgroundColor` (config) and iOS `ios.backgroundColor` = `#f9fafb`.
- SplashScreen background `#ffffff`, launch screen shows the Kitcha logo centered (existing brand asset), no spinner, `launchAutoHide: false` then hide once first React paint completes (max 2s timeout), fade 200ms.
- StatusBar: `Style.Light` in Capacitor terms (dark text/icons for light backgrounds), `overlaysWebContent: true`, background transparent; the header's `pt-safe` supplies the colored area behind the status bar (white header). Set once at startup; do not change per route. Scan screen: same style (camera preview is behind a white-chrome overlay, see Scan section).
- Expiry/budget semantic colors unchanged (`expiry-ok/warning/critical`).

## Native Behavior Contract (SHELL-05)

### Viewport and safe areas
- `viewport-fit=cover` already set (layout.tsx). Keep. Add `maximum-scale=1, user-scalable=no` ONLY under native via viewport config conditional on `BUILD_TARGET=native`; web keeps pinch-zoom (accessibility).
- Every fixed/sticky element pads for insets: header (top), bottom tab bar and More sheet (bottom), full-height sheets (top and bottom), toasts (bottom offset = tab bar + inset + 8px), modal footers (bottom).
- Landscape: lock to portrait in Info.plist (iPhone) for v1; left/right insets still honored via `pl-[env(safe-area-inset-left)]` on the shell.
- Use `h-dvh` (already present) for the shell; never `100vh`.

### Scrolling and rubber-band
- `html, body { overscroll-behavior: none; position: fixed; inset: 0; width: 100%; height: 100%; overflow: hidden }` under native only (class `native` on `<html>` set before first paint from `Capacitor.isNativePlatform()`, with a build-time `BUILD_TARGET=native` default so there is no flash).
- Capacitor config `ios.contentInset: 'never'` (insets handled in CSS) and `ios.scrollEnabled: false` (WebView-level scroll disabled; only inner containers scroll).
- The single scroll container is the existing `<main class="overflow-y-auto overscroll-contain">`; add `-webkit-overflow-scrolling: touch`. Inner bounce at the list ends is ALLOWED (native feel); chaining to the page is not.
- No pull-to-refresh in this phase.

### Keyboard
- `@capacitor/keyboard` config: `resize: 'native'`, `resizeOnFullScreen: true`, `style: 'light'`, `accessoryBarVisible: true` is hidden (`Keyboard.setAccessoryBarVisible({ isVisible: false })`) except inside multi-field forms.
- Focused input must scroll into view with 16px clearance above the keyboard (call `scrollIntoView({ block: 'center' })` on `keyboardDidShow` for the active element inside sheets).
- Bottom tab bar hides while the keyboard is open (class on `<html>`: `keyboard-open` on `keyboardWillShow`, removed on `keyboardWillHide`) so it does not float above the keyboard. Sheet footers with primary actions stay visible above the keyboard.
- Tapping outside a text field on non-interactive background dismisses the keyboard; scrolling the list does too (`scrollEnabled` interactive dismiss via `Keyboard.hide()` on scroll start).

### Haptics (`@capacitor/haptics`)
Single wrapper `haptic(kind)` that no-ops on web and when Reduce Motion is NOT the criterion (haptics are not motion); also no-ops if the user disabled "Haptics" in Settings (new Switch, default on). Fire on press-down completion, never on render.

| Action | Feedback |
|--------|----------|
| Check / uncheck shopping item | `ImpactStyle.Light` |
| Quantity stepper +/- (pantry) | `ImpactStyle.Light` per step; at min/max boundary `NotificationType.Warning` |
| "Cooked it" confirm | `NotificationType.Success` |
| Barcode scan success (resolved product) | `NotificationType.Success` |
| Scan unknown product / lookup failed | `NotificationType.Warning` |
| Finish shopping trip | `NotificationType.Success` |
| Destructive confirm (delete account, remove item) | `NotificationType.Warning` on open of confirmation; none on cancel |
| Bottom tab change | `selectionChanged` (`Haptics.selectionStart/Changed/End`) |
Limit: no more than one haptic per 80ms; never on scroll, page load, or background refresh.

### Share (`@capacitor/share`)
- Shopping list screen: "Share list" icon button (lucide `Share`, 44px, `aria-label="Share shopping list"`) in the header action row. Native: opens the iOS share sheet with plain text: title "Kitcha shopping list", body lines `[ ] Item (qty unit)` grouped by category header, unchecked items only. Web: unchanged (Web Share API if present, else copy-to-clipboard with toast "List copied").
- If `Share.canShare()` is false or the call rejects with non-cancel error: toast "Couldn't open sharing. Try again." User cancel is silent.

### Platform-conditional UI (via `isNative()` from Capacitor; one helper, one hook `usePlatform()`)
| Element | Web | Native iOS |
|---------|-----|------------|
| iOS "Add to Home Screen" hint (`components/pwa/ios-install-hint.tsx`) | shown per existing rules | NEVER rendered |
| PWA install prompt / manifest links | present | not rendered |
| Barcode scanning | WASM `barcode-detector` camera view | native scanner via adapter |
| Share | Web Share / clipboard | iOS share sheet |
| Haptics Switch in Settings | hidden | shown |
| Reminder (local notification) settings | hidden (existing in-app alerts only) | shown |
| Stripe / web checkout | n/a this phase | must stay hidden (rule 3.1.1) for later phases |
| Keyboard accessory, status bar, splash | n/a | configured as above |
| Hover-only affordances | allowed | remove; use pressed states (`active:`) |
Pressed state: all tappable rows/cards get `active:bg-gray-100` (cards) within 0ms, no 300ms delay (`touch-action: manipulation` already global).

## Native Scan Sheet (SHELL-03)

Reuse `components/pantry/scan/scan-sheet.tsx` and its `ScanState` machine; the adapter swaps only the "scanning" engine. Existing states, copy, and manual entry remain; Phase 6 resolution flow unchanged.

- Native scanner presents its own full-screen camera UI (OS-level). Our contract is the surfaces around it:
  1. Tapping "Scan barcode" in Pantry add flow: immediately invoke native scanner (no intermediate sheet) when permission granted. First time: iOS camera permission prompt appears; precede it with NO custom pre-prompt (the native Info.plist string is the explanation).
  2. If the native scanner supplies a cancel/close control, it returns to the pantry screen unchanged (no toast).
  3. On a code: haptic Success, then existing `looking-up` state renders in the sheet over the normal white UI ("Looking up product"), then the existing resolution cards.
- If the plugin requires a transparent WebView (camera behind DOM): while scanning, `html.scanning` sets `background: transparent` on `html, body, #app shell`, hides header and tab bar, and only the following overlay is visible: a top bar (safe-area aware) with a 44px close button and title "Scan barcode"; a centered 260 x 160px viewfinder with 24px corner brackets, 4px stroke, accent `#0ea5e9`; helper text below in white, Body 16px/400, with a `rgba(0,0,0,0.5)` pill backing (contrast >= 4.5:1); a bottom button row (inset-aware) with "Enter code instead" (secondary, 48px). Remove `html.scanning` on every exit path (success, cancel, error, unmount).
- Info.plist `NSCameraUsageDescription`: "Kitcha uses the camera to scan product barcodes so you can add food to your pantry quickly. Photos are never saved."
- Denied permission: reuse `CameraDeniedCard` with native variant action "Open Settings" (App.openSettings / `UIApplication.openSettingsURLString`) in addition to "Enter code instead". Never a dead end: manual entry always available.
- Simulator / no camera: `isSupported` false routes to `manual` state directly (existing `ScanUnsupportedCard` copy). Test hook: `?testCode=` equivalent via injected adapter, only compiled when `NEXT_PUBLIC_E2E=1`.

## Notification Opt-in and Reminders (SHELL-04)

Principle (Apple 5.1.2(i)): reminders are never required to use the app; the iOS permission prompt is requested only after the user taps an in-app opt-in. Never prompt at launch, signup, or login.

### Entry points
1. Contextual card on Dashboard / Alerts when native, permission `prompt` state, and user has at least 1 pantry item with an expiry date: dismissible `Card` ("Not now" remembers for 14 days).
2. Settings > Reminders section (native only): master `Switch` "Expiry reminders" plus sub-settings.

### Explainer sheet (bottom sheet, Radix Dialog, slide-up 300ms, handle bar, inset-aware, max-height 85dvh)
Contents top to bottom (gap 16px, padding 24px):
- Icon tile 48px, `bg-primary-50`, lucide `BellRing` in primary-600.
- Heading (20/600): "Never waste food by surprise"
- Body (16/400, gray-600): "Kitcha can remind you before things in your pantry expire. Reminders are set up on your phone and work even offline."
- Preview row (Card, gray-50): bell icon + sample text "Milk expires tomorrow. Plan to use it today." (Label 14/600 title, Body 16/400 detail).
- Primary Button `lg` full width: "Turn on reminders" -> triggers `LocalNotifications.requestPermissions()`.
- Ghost Button `lg` full width: "Not now" -> closes, sets 14-day snooze, no haptic.
- Fine print (14px/600 NOT used; use Body 16/400 gray-500): "You can change this anytime in Settings."

### Post-prompt states
| State | UI |
|-------|----|
| Granted | Sheet closes, haptic Success, toast "Reminders are on", schedule immediately, Settings switch on |
| Denied (iOS) | Sheet content swaps to: heading "Reminders are off", body "Turn on notifications for Kitcha in iOS Settings to get expiry reminders.", primary "Open Settings", ghost "Close". Settings switch shows off with helper "Notifications are blocked in iOS Settings." and an "Open Settings" text button (44px). |
| Provisional/unknown | Treated as denied copy above |
| Schedule error | Toast (error) "Couldn't schedule reminders. We'll retry when you reopen the app." (retry on app resume) |

### Reminder settings (native only, inside Settings > Reminders)
- `Switch` "Expiry reminders" (reflects OS permission AND user preference; turning ON when OS denied opens the Denied sheet).
- "Remind me" select: "Morning of expiry" / "1 day before" (default) / "2 days before" / "3 days before" (multi-select via chips; at least one must stay selected, otherwise switch turns off).
- "Reminder time": time select, default 9:00 AM, 30-minute steps.
- Existing global notification preferences (Phase earlier) remain the source of truth; local scheduling must respect them, and this UI only edits the native-specific bits.
- Scheduling rule (display contract): one notification per day per timing, grouping items: single item "Milk expires tomorrow" / multiple "3 items expire tomorrow: Milk, Eggs, Spinach" (list truncated to 3 names then "and N more"). Title: "Kitcha". Tapping deep-links to Pantry filtered to expiring (`/pantry/?filter=expiring`, query param, no dynamic route). Rebuild the schedule on pantry change and app resume; cap at 60 pending (iOS limit is 64).

## Interaction States and Accessibility

- Every new control: default, pressed (`active:`), disabled (opacity 50), loading (Button `loading`), focus-visible ring (primary-500, 2px, offset 2px). VoiceOver labels on all icon-only buttons; sheets are `role="dialog"` with focus trap (Radix); "Close" is the first focusable in sheets.
- Motion: sheets slide-up 300ms ease-out, fades 200ms. `prefers-reduced-motion` already collapses durations globally; keep. Splash fade 200ms.
- Contrast: text >= 4.5:1 on white/gray-50; white text on `#0ea5e9` is 2.9:1 and FAILS for body text, so primary Buttons keep 16px/600 (large-ish) but use primary-600 `#0284c7` (4.1:1) at rest and 700 pressed for any new native CTAs; executor must match existing Button variant and not introduce new blues. (Flag for checker: existing `primary` variant uses 500.)
- Tab bar: 5 items max, icon 24px + label 14px/600... label uses Label role; active = primary-600 icon+label, inactive gray-500; existing `components/dashboard/bottom-nav.tsx` and `more-sheet.tsx` are reused, only inset/keyboard behavior is added.

## Checker Recommendations Accepted
