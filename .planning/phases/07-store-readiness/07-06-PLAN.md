  <behavior>
    - User A with pantry item, recipe R, meal plan whose item references R, shopping list + item, shopping history, preferences, notification, alert, zapier webhook, ai_report, ai_usage 'user:A' -> DELETE /users/me {password} -> 204; every one of those rows for A is gone (count 0)
    - Same fixtures for user B -> all B rows still present (count 1 each); ai_usage 'global' row still present
    - Wrong password -> 403, body.code 'INVALID_PASSWORD', every A row still present, A can still call GET /users/profile (200)
    - Missing password -> 400; empty string -> 400
    - After 204: GET /users/profile with the old token -> 401; POST /auth/login with old credentials -> 401
    - Completeness: models = Prisma.dmmf.datamodel.models filtered to those with an object field of type 'User'; for every such model the fixture map has a factory, else the test fails with "No deletion fixture for model X"
    - Unauthenticated DELETE /users/me -> 401
  </behavior>

    `deleteAccountPermanently(userId, password)`: load passwordHash (select only that); if missing throw AppError('User not found', 404). `comparePassword` outside the transaction; on mismatch throw `new AppError('That password is incorrect. Then `prisma.$transaction(async (tx) => { await tx.mealPlanItem.deleteMany({ where: { mealPlan: { userId } } }); await tx.aiUsage.deleteMany({ where: { scope: `user:${userId}` } }); await tx.user.delete({ where: { id: userId } }); })` (cascades the rest). Log `logger.warn('User account permanently deleted', { userId })` with no email/PII.
  </implementation>
