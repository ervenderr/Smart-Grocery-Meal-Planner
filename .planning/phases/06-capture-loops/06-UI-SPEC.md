## Spacing Scale

Multiples of 4 only, same tokens as [P3]: xs 4, sm 8, md 16, lg 24, xl 32, 2xl 48, 3xl 64.

Exceptions (each justified):
- 44px (`min-h-11 min-w-11`): all touch targets below `lg`, including stepper buttons, chips, sheet shortcut buttons, toggle row [P3].
- 48px (`min-h-12`): shortcut rows and list rows inside sheets [P3].
- 56px (`h-14`): stepper numeric field width is `w-14` (56px) x 44px height, so 3-4 digit values with unit fit at 16px. Between tokens, multiple of 4.
- Scan viewfinder reticle: `w-64 h-40` (256 x 160px) centered, `rounded-xl`; multiples of 4, sized for a 1D barcode aspect ratio.
- Safe-area insets added on top of tokens (`pt-safe`, `pb-safe`) [P3].
- No 12px values: use `gap-2` / `gap-4`.

## Typography

Exactly 4 sizes and 2 weights, same as [P3]. No `text-xs`. No `font-bold` / `font-medium`.

| Role | Size | Weight | Line Height | Tailwind | Phase 6 usage |
|------|------|--------|-------------|----------|---------------|
| Body / inputs | 16px | 400 | 1.5 | `text-base` | Sheet body text, all inputs (stepper numeric field, date, barcode field), toggle label |
| Label / secondary | 14px | 600 labels, 400 secondary | 1.43 | `text-sm` | Chips, shortcut buttons, preview table cells, "used up" badge, helper and error text, scan hint |
| Heading | 20px | 600 | 1.4 | `text-xl` | Sheet titles ("Scan barcode", "Cooked it?", "Change expiry date") |
| Display | 24px | 600 | 1.33 | `text-2xl` | Not used in this phase |

Stepper value uses `text-base font-semibold` (16px, 600) with tabular figures (`tabular-nums`) so the number does not jitter between steps.

## Color

Unchanged palette [P3]. 60/30/10:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff`, `gray-50` | Sheets, cards, preview table, toggle row |
| Secondary (30%) | `gray-100/200` borders and pressed states, `gray-500/600/900` text | Stepper button borders, table dividers, helper text, skipped-ingredient list |
| Accent (10%) | `primary-500` `#0ea5e9`, `primary-50` tint, `primary-700` text on tint | See reserved list |
| Destructive | `red-500` / `red-600` | "Remove" on used-up item, scan error icon only if it blocks nothing (it does not: use amber, see below) |

Accent reserved for (this phase only):
1. Primary CTAs: "Apply deductions", "Save date", "Add to pantry" in the finish sheet (existing finish button) [P3 rule: `Button variant="primary"`].
2. Scan reticle corner brackets and the "Scan" button focus ring.
3. Selected/on state of the "Add checked items to pantry" switch (`bg-primary-500` track).
4. Focus rings (`focus-visible:ring-primary-500`).
5. The selected expiry shortcut chip after tap (`bg-primary-50 border-primary-500 text-primary-700`).
6. The "You've added this before" banner on the Add form (`bg-primary-50 text-primary-700`).
7. The recipe-detail "Cooked it" button (`Button variant="primary"`, covered by rule 1 as the single primary CTA of that modal footer).
8. The 150ms stepper value flash (`bg-primary-50`).

Semantic (reuse existing, no new tokens):
- "Used up" badge: `bg-gray-100 text-gray-700 border border-gray-300` (neutral, not an error, not accent).
- Low-stock after deduction (left < have, left > 0): neutral text. Left = 0 renders `text-gray-900 font-semibold` plus the "Used up" badge.
- Insufficient / unconvertible rows in the cook preview, scan "unknown product" and permission notices: amber (`bg-amber-50 border-amber-200 text-amber-800`, icon `AlertTriangle`), already in use for expiry warnings [AUDIT]. Never red for recoverable states.
- Camera overlay: `bg-black` full-bleed behind the video; overlay text and controls are white on `bg-black/60`. This is the one dark surface in the app and is scoped to the scan sheet only; it does not change the "light only" theme rule.
- Expiry status colors on the card chip remain the existing `expiry-*` styles.

### 2. Scan camera sheet

Full-screen sheet: NOT the shared bottom-sheet Modal (needs full-bleed video). `fixed inset-0 z-50 h-dvh bg-black`, built on Radix Dialog for focus trap, `Escape`, `aria-modal`, title `sr-only`/visible per state. Uses `pt-safe pb-safe`. `animate-fade-in` (none under reduced motion). Component `components/pantry/scan/scan-sheet.tsx`; state machine in `use-barcode-scanner.ts`.

Layout (top to bottom):
- Top bar (`h-14 px-4 bg-black/60 pt-safe`): Close `X` button 44x44, `aria-label="Close scanner"`, white; title "Scan barcode" (`text-xl font-semibold`, white); right side torch toggle (`Flashlight` icon, 44x44, `aria-pressed`, shown only when the track reports torch capability).
- Video area: `<video playsInline muted autoPlay>` `object-cover` filling the middle. Reticle 256x160 with 4 corner brackets `border-primary-500` (4px corners, `rounded-xl`), dimmed surround `bg-black/50`.
- Bottom panel (`bg-black/60 px-4 py-4 pb-safe`): hint text (`text-base`, white, centered) and a text button "Type the barcode instead" (`min-h-11`, white underlined `text-sm font-semibold`).

States (each with exact copy):

| State | Visual | Copy | Actions |
|-------|--------|------|---------|
| Requesting camera | Black screen, centered spinner (`Loader2`, 32px, white, `animate-spin`) | "Starting camera..." | Close only |
| Scanning (ready) | Video + reticle, hint at bottom | Hint: "Point your camera at the barcode." Second line after 8s with no detect: "Hold steady and make sure there is enough light." | Torch (if available), "Type the barcode instead", Close |
| Detected, looking up | Reticle brackets pulse once, video frozen on last frame, `Loader2` + text; vibrate 50ms if `navigator.vibrate` exists | "Looking up {barcode}..." | Close (cancels) |
| Product found | Sheet closes, Add Pantry modal opens prefilled (name, brand in notes, category via `inferCategory`, quantity/unit from product quantity when parseable else 1 pcs, `barcode` set). Toast: "Product found. Check the details and save." | n/a | Normal form |
| Unknown product (OFF 404 or no name) | Video stops; panel switches to amber notice card (`AlertTriangle`) | Title: "We don't know this product yet" Body: "Barcode {barcode} isn't in Open Food Facts. You can still add it yourself and we'll remember the barcode." | Primary "Add manually" (opens Add Pantry modal with barcode kept, name empty and focused), secondary "Scan again" |
| Lookup failed (network / 429 / 5xx) | Same amber card | Title: "Couldn't look up this product" Body: "Check your connection and try again, or add it manually. The barcode is saved either way." | Primary "Try again", secondary "Add manually" |
| Permission denied | No video; centered icon `CameraOff` (48px, white/gray-300) on black | Title: "Camera access is off" Body: "Allow camera access in your browser settings to scan, or type the barcode instead." iOS standalone variant adds: "On iPhone: Settings > Safari > Camera, or Settings > Kitcha." | Primary "Type the barcode" (goes to manual state), secondary "Try again" (re-requests), Close |
| No camera / insecure context / not supported | Same layout as denied | Title: "Scanning isn't available here" Body: "This device or browser can't use the camera. Type the barcode instead." | Primary "Type the barcode", Close |
| Manual barcode | Black background replaced by `bg-white` panel (sheet becomes a standard light sheet; video stopped and stream released) | Title "Type the barcode" (`text-xl`); label "Barcode"; input `inputMode="numeric"` `pattern="[0-9]*"` `maxLength=14` 16px, placeholder "e.g. 4800016644801"; helper "8 to 14 digits, found under the barcode." Validation error: "Enter 8 to 14 digits." | Primary "Look up barcode" (disabled until 8-14 digits), secondary "Scan with camera" (returns to scanning, hidden when camera unavailable), "Add without a barcode" text button (opens empty Add Pantry modal), Close |

Behavior rules:
- Lazy-load `barcode-detector` polyfill only when the sheet first opens and `'BarcodeDetector' in window` is false. While loading show the "Starting camera..." state.
- Formats: EAN-13, EAN-8, UPC-A, UPC-E (and Code 128 as bonus). Debounce: accept the first detection, ignore repeats while looking up.
- Stop all tracks (`track.stop()`) on close, on detect, on switching to manual, and on unmount; camera indicator must go off.
- Pausing: if the tab becomes hidden, stop the camera; on return show scanning state again.
- Repeat scans: if the barcode already exists on a user pantry item, the Add modal opens prefilled from that item (name, category, unit) with banner (`bg-primary-50 text-primary-700 rounded-lg p-2 text-sm`): "You've added this before. Details filled in from your pantry." Quantity left at 1 and expiry empty.
- Open Food Facts attribution: reuse `food-data-attribution.tsx` under the prefilled form when data came from OFF (existing component, `text-sm text-gray-500`).
- Errors never block: every error state offers a path to the manual form with the barcode preserved [CTX].

### 3. Add / Edit pantry form changes

Used to fill details when you scan this again." Prefilled-from-scan fields get no special color; the OFF attribution line is the only marker.

### 4. Pantry card: quantity stepper

Placement inside `pantry-item-card.tsx` [AUDIT: current card shows quantity as text line and Edit/Delete icon buttons `h-11 w-11`]: replace the quantity text line with a stepper row below the name/category; Edit and Delete icon buttons stay on the right.

```
[ - ]  [ 250 ] g  [ + ]
```

| Part | Spec |
|------|------|
| Minus button | `h-11 w-11` rounded-lg `border border-gray-300 bg-white`, icon `Minus` 20px, `aria-label="Decrease {name} quantity"`, disabled at 0 (`opacity-50`, `aria-disabled`) |
| Value | `w-14 h-11` button showing the number (`text-base font-semibold tabular-nums`, centered) followed by unit text (`text-sm text-gray-600`) outside the box. Tap converts to inline numeric input (`inputMode="decimal"`, 16px, auto-select); Enter or blur commits, Escape cancels. `aria-label="Edit {name} quantity, currently {n} {unit}"` |
| Plus button | same as minus, icon `Plus`, `aria-label="Increase {name} quantity"` |
| Gap | `gap-2` between parts (8px); the whole row has a 44px height |

Step sizes [CTX, DEFAULT values]: pcs/pieces/each 1; g 50; kg 0.25; ml 50; l 0.25; oz 1; lb 0.25; cup 0.25; tbsp 1; tsp 1; can/pack/bottle/box 1; unknown unit 1. Hold-to-repeat not included. Display rounds to at most 2 decimals, trailing zeros trimmed (`0.25`, `1.5`, `250`).

Behavior:
- Optimistic update with 400ms debounce per item; one PATCH with the final value; rollback to the last server value plus toast on error: "Couldn't update {name}. Your change was undone." Never allow < 0 (minus clamps to 0; direct entry rejects negatives with inline `text-sm text-red-600` "Enter 0 or more."). Direct entry max 99999; larger shows "That number is too large."
- Announce changes via a polite live region: "{name}: {n} {unit}".
- Value flashes `bg-primary-50` for 150ms on change (skipped for reduced motion).

### 6. Expiry bottom sheet [CTX]

Trigger: the expiry chip on the card becomes a `button` (44px min height via `min-h-11 px-2`). When no expiry is set show a dashed-outline chip "Add expiry date" (`Calendar` icon, `border-dashed border-gray-300 text-gray-600`) so the sheet is reachable. `aria-label="Change expiry date for {name}, currently {date}"`.

Sheet: shared `Modal` (`size="sm"`, bottom sheet below `sm`), title "Expiry date" (heading `text-xl`), subtitle `text-sm text-gray-600` = item name.

Contents (top to bottom, `space-y-4`):
1. Date input: label "Expires on", `<input type="date">` 16px, `h-11 w-full`, prefilled with the current value; `min` not enforced (past dates allowed for already-expired items).
2. Shortcut row (label "Add days to the date above", `text-sm font-semibold`): 3 chips `+1 day`, `+3 days`, `+7 days`, each `h-11 px-4 text-sm font-semibold rounded-lg border border-gray-300`, equal width in a 3-col grid with `gap-2`. Rule: +N days adds N days to the value currently in the date field, falling back to today when the field is empty or in the past. Tap sets the date input (does not save); the chosen chip shows the selected style briefly. Label "Add days to the date above" and helper under row: "Adds days to the date in the field, or to today if it is empty or already past."
3. Footer buttons: "Clear date" (`variant="outline"`, shown only when a date exists; `Button`, h-11), "Keep current date" (outline, closes without saving), "Save date" (primary). Stacked `flex-col-reverse` below `sm` [P3]. "Clear date" clears the field and saves immediately with toast "Expiry date cleared."
- Save: PATCH `expiryDate`; optimistic on card; success toast "Expiry date updated."; error toast "Couldn't update the expiry date. Try again." (sheet stays open, value retained).
- Validation: invalid or empty date with "Save date" tapped: inline error "Pick a valid date, or use Clear date."

### 7. Finish-shopping "Add to pantry" toggle [CTX]

In `components/shopping/finish-sheet.tsx` [AUDIT: 94 lines]. A row between the summary and the footer buttons:

- Row: `min-h-14 rounded-lg border border-gray-200 bg-white p-4 flex items-center justify-between gap-4`, whole row is the `<label>` target (44px+ hit area).
- Left: title `text-base font-semibold` "Add checked items to pantry"; helper `text-sm text-gray-600` (dynamic): "{n} items will be added or merged into your pantry." (n = checked items; singular "1 item will be added or merged into your pantry."). Off state helper: "Your pantry won't change."
- Right: switch (`role="switch" aria-checked`), track `h-8 w-14` (32x56px; same spacing exception as bottom-nav pill) `rounded-full`, on = `bg-primary-500`, off = `bg-gray-300`, white 24px thumb with 4px inset; label text exposed via `aria-labelledby`.
- Default ON each time the sheet opens. No persistence between sessions [DEFAULT].
- Disabled (off, with helper "No checked items to add.") when 0 items are checked.
- Primary button label stays the existing finish label; when toggle is ON the button text gains no change; the post-finish toast carries the result.
- Success toast (merge-aware): "Shopping finished. {a} added to your pantry, {m} merged." with parts omitted when 0, e.g. "Shopping finished. 5 items added to your pantry." Toggle off: existing finish copy unchanged.
- Partial failure (list finished, pantry add failed): toast (error) "Shopping finished, but we couldn't update your pantry. You can add the items manually." Never roll back the finish.
- No per-item prompt on check-off [CTX].

### 8. "Cooked it" entry points and preview/confirm sheet

Entry points:
- Recipe detail (`recipe-detail-modal` header action area or footer): button `Button variant="primary"` with `ChefHat` icon, label "Cooked it", `h-11`, full-width below `sm`.
- Meal-plan item (inside `meal-plan-detail-modal` per-meal row and `meal-plan-card` action row where applicable): secondary icon+label button "Cooked it" `h-11 text-sm` (matches 03 action row contract).
- Meal-plan item already cooked: button replaced by a non-interactive badge `CheckCircle` + "Cooked" (`bg-gray-100 text-gray-700 rounded-full px-2 py-1 text-sm font-semibold`) with title attribute; cannot be applied twice [CTX]. Tap on badge: no action.

Sheet: shared `Modal` (`size="md"`), title "Cooked it?" (`text-xl`), subtitle: recipe name (`text-base`, truncate).

Content:
1. Servings control (only for recipe detail; for meal-plan item it shows the planned servings, editable): label "Servings you cooked", number stepper using the same 44px minus/value/plus component as pantry (step 1, min 1, max 99). Changing it recomputes the preview (scaling by servings / recipe servings) immediately, client-side from the preview response or server re-fetch debounced 300ms [DEFAULT].
2. Preview list (`role="list"`, header row only from `sm`): one row per recipe ingredient that matches a pantry item. Below `sm` each row is a stacked card (`rounded-lg border border-gray-200 p-4 space-y-2`):
   - Line 1: item name (`text-base font-semibold`, truncate).
   - Line 2: three labelled values in `grid grid-cols-3 gap-2`, `text-sm`, labels `text-gray-600` and values `text-gray-900`: "Have 500 g", "Use [ 200 ] g" (editable), "Left 300 g" (updates live, `font-semibold`).
   - "Use" is an inline numeric input `h-11 w-full` 16px (`inputMode="decimal"`), pre-filled with the computed deduction in the pantry item's unit; min 0, max = have (cannot exceed have; if the user types more: clamp and show "Only {have} {unit} in your pantry.").
   From `sm`: a 4-column table (Item, Have, Use, Left) with the same values.
   - A row with Use = 0 is "skipped".
3. Notes block, amber style, only when non-empty, grouped and each with `AlertTriangle`:
   - Not in pantry: heading `text-sm font-semibold` "Not in your pantry (skipped)"; list of names in `text-sm`. If there are many (>5) collapse to "{n} more" disclosure button (44px).
   - Can't convert (different unit family): "Different units (skipped)" list as "{name}: recipe uses {x} {unit}, pantry has {y} {unit}". Each row has "Enter amount" link-button focusing the Use input after enabling it (user may override manually, same unit as pantry).
   - Staples: "Staples (not deducted)" listing e.g. "salt, oil" (`text-sm text-gray-600`, neutral not amber).
   - Short on stock: when computed use exceeds have: row shows `Left 0` and an inline text "Only {have} {unit} in your pantry. Using all of it." (amber text).
4. Footer: "Discard changes" (outline, closes without applying; plain "Close" when no Use value was edited), "Apply deductions" (primary). Primary shows count in the helper line above footer: "{n} items will be updated." Disabled with helper "Nothing to deduct." when every row is skipped/zero or none match; in that case a third action is not offered but "Mark as cooked" appears as the primary for meal-plan items so they can still be flagged: label "Mark as cooked" (no deductions). For recipe detail with nothing to deduct only "Close".

## Accessibility

- Scan sheet: Radix Dialog with `aria-modal`, visible title, focus lands on Close on open and returns to the trigger on close; `Escape` closes; live region (`role="status"`, `aria-live="polite"`) announces state changes ("Camera ready. Point at a barcode.", "Barcode detected.", "Product not found."). Video has `aria-hidden="true"`; the "Type the barcode instead" path is always reachable by keyboard and screen reader, so scanning is never the only route.
- Stepper: buttons are real `<button>`s with `aria-label`s above; value is a button toggling to `<input>`; group has `role="group" aria-label="Quantity for {name}"`.
- Expiry chip and shortcut chips: `<button>`; shortcut chips group `role="group" aria-label="Quick expiry shortcuts"`.
- Switch: `role="switch"`, Space/Enter toggles, visible focus ring `ring-primary-500`.
- Cook preview: table semantics from `sm` (`<table>` with `<th scope>`); stacked cards below `sm` use `role="list"`/`listitem` and each value has a visible text label (not color-only). Use inputs labelled "Use {name} ({unit})".
- Contrast: white text on `bg-black/60` over video is not guaranteed; text blocks use an opaque `bg-black/70` backing. Amber notices `amber-800` on `amber-50` >= 4.5:1.
