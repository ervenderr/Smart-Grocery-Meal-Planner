Contracts this plan CREATES (06-08 extends the service; 06-10 consumes the HTTP shapes):
- cook.plan.ts:
  - `cookKey(name: string, unit: string): string` = `${canonicalName(name)}|${familyKey(resolveUnit(unit))}` (pipe-delimited, safe in JSON).
  - `interface CookLot { id: string; ingredientName: string; quantity: unknown; unit: string; expiryDate: Date | null; createdAt: Date }`.
  - `type CookRowStatus = 'ok' | 'short' | 'mismatch'`.
  - `interface CookRow { key: string; name: string; unit: string; have: number; use: number; left: number; status: CookRowStatus; recipeQuantity?: number; recipeUnit?: string }` (name = first FEFO lot's ingredientName; unit = first FEFO lot's unit; have = sum of the key's usable lots converted to that unit, round2; for mismatch rows use 0, left = have, and recipeQuantity/recipeUnit describe what the recipe asked for).
  - `interface CookPlan { rows: CookRow[]; notInPantry: string[]; staples: string[]; ingredientCount: number }`.
  - `computeCookPlan(args: { recipe: { servings: number; title: string; ingredientsList: unknown }; servings: number; lots: readonly CookLot[]; staples: ReadonlySet<string>; todayUtc: Date }): CookPlan`.
  - `allocateDeduction(args: { lots: readonly CookLot[]; key: string; unit: string; use: number; todayUtc: Date }): { updates: { id: string; quantity: number }[]; usedUp: number }` (usable lots of that key in FEFO order: expiryDate asc, null last, then createdAt asc; use converted to base via resolveUnit(unit); each lot's new quantity = round2(fromBase(max(haveBase - takeBase, 0), lotUnitKey)); total take clamped to total have; zero-take lots are not returned; throws a typed error when unit's family differs from the key's family).
- HTTP:
  - `POST /api/v1/cook/preview` body `{ recipeId: uuid, servings?: int 1..99 }` -> 200 `{ recipe: { id, title, servings }, servings, rows: CookRow[], notInPantry: string[], staples: string[], ingredientCount: number, mealPlanItemId: null, alreadyCooked: false }`.
  - `POST /api/v1/cook/apply` body `{ recipeId: uuid, deductions: { key: string (1..200), unit: string (1..20), use: number 0..99999 }[] (max 100, unique keys) }` -> 200 `{ updated: number, usedUp: number, skipped: number }`.
  - Errors: 404 `{ code: 'RECIPE_NOT_FOUND' }`; 400 `VALIDATION_ERROR` for bad bodies, duplicate keys, or a unit whose family differs from the key.
- `COOK_ERROR_CODES = { RECIPE_NOT_FOUND, ALREADY_COOKED, MEAL_NOT_FOUND, DEDUCTION_UNIT_MISMATCH }` in cook.constants.ts (06-08 uses ALREADY_COOKED/MEAL_NOT_FOUND), plus `COOK_PANTRY_READ_CAP = 2000`, `MAX_DEDUCTIONS = 100`, `MAX_SERVINGS = 99`.

## Trust Boundaries

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Elevation of privilege | apply on other users' pantry | mitigate | Lots read with `where: { userId, deletedAt: null }` inside the tx; updates only for ids from that read; test with a second user's same-name lot |
| T-06-07 | Information disclosure | preview of another user's private recipe | mitigate | Access rule `OR [{ userId }, { isPublic: true }], deletedAt: null`; 404 RECIPE_NOT_FOUND (no existence leak) |
| T-06-08 | Tampering | forged use above stock / negative / NaN | mitigate | Validation 0..99999 toFloat; allocateDeduction clamps total take to server-read have; Decimal math; floor 0 |
| T-06-09 | Denial of service | huge deductions arrays / pantry scans | mitigate | `deductions` max 100, unique keys, key length <= 200; pantry read capped at 2000; global apiLimiter |
| T-06-10 | Tampering | partial writes on failure | mitigate | All writes inside one `prisma.$transaction`; mismatch error rolls back; test asserts nothing changed |
| T-06-SC | Tampering | npm installs | accept | No packages installed in this plan |
</threat_model>
