<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Railway runtime -> container | Platform injects env vars (PORT, DATABASE_URL) and sends SIGTERM on redeploy |
| Operator shell -> production DB | `railway run`/`railway ssh` could execute the seed against production |
| npm registry -> backend deps | New dependency zod plus a prisma pin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | backend/prisma/seed.ts | mitigate | Guard exits 1 when NODE_ENV=production before PrismaClient is created, so the demo user with a known password cannot be created in prod |
| T-01-02 | Denial of Service | backend/entrypoint.sh | mitigate | `exec node` makes node PID 1 so SIGTERM reaches the graceful-shutdown handler; migration retry is capped at 5 and exits non-zero on real failures |
| T-01-03 | Tampering | backend/Dockerfile | mitigate | Remove hard-coded PORT so the domain target port matches the injected PORT; CHECKPOINT_DISABLE stops outbound Prisma telemetry from the runtime |
| T-01-04 | Information Disclosure | backend/README.md, test env | mitigate | No secret values in README or committed files; test JWT_SECRET is generated per run with openssl |
| T-01-SC | Tampering | npm installs (zod, prisma pin) | accept | zod is [OK] in the RESEARCH Package Legitimacy Audit (6.6 yrs, ~387M/wk); prisma/@prisma/client are exact pins of the already-locked 5.22.0; no [ASSUMED]/[SUS] packages |
</threat_model>
