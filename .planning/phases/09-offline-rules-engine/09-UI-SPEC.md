# Phase 9 — UI Design Contract

> Visual and interaction contract for the "Cook from what you have" ranked list and the "Substitute" affordance. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: web app UI in `frontend/` (which the Capacitor shell in Phase 10 wraps). `mobile/` currently contains only a README, so "existing mobile UI conventions" means the mobile-first conventions of the `frontend/` app (bottom-sheet modals, 44px targets, safe areas, 16px inputs). Cooking/deduction is NOT in scope (Phase 11); the UI only links to the existing recipe detail.

Sources: 09-CONTEXT.md (locked: surface in web app, ranked list + Substitute for missing ingredients, works with network off from React Query cache, explainable have/missing/expiring-used, follow existing design system), ROADMAP Phase 9 success criteria, scan of `frontend/` (globals.css, components/ui, cook-first-card, recipe-card, Modal, EmptyState, lib/navigation.ts).

## Placement and Layout

Default chosen (CONTEXT left placement to discretion):

1. **Route:** new page `app/(app)/recipes/cook/page.tsx`, title "Cook from what you have". Add `PAGE_TITLES['/recipes/cook']` in `lib/navigation.ts`. Static-export friendly, no server data fetch at render.
2. **Entry points (two, no new tab-bar item):**
   - Recipes page header: add an `outline` Button "Cook from what you have" (icon `ChefHat`) before "AI Suggestions". Mobile: full width stacked; sm+: inline.
   - `CookFirstCard` on Home: add a text link "See all you can cook" at card bottom (min-h 44px) routing to `/recipes/cook`. (Existing card behavior unchanged.)
3. **Page structure (top to bottom), single column on mobile, `space-y-4`:**
   - Header: h1 "Cook from what you have" (24px/600) + one-line body "Ranked by what is in your pantry. Works without internet." (14px, gray-600).
   - Filter Card (`p-4`): diet/exclusion toggle chips in a horizontally scrolling row (`scrollbar-hide`, 44px chips, same style as Recipes category chips, `aria-pressed`): "Hide recipes with excluded ingredients" is driven by user preferences (read-only summary line "Diet: vegetarian, no peanuts" with link "Change in profile") plus one chip "Only recipes I can make now" (missing count = 0). No search box in this phase.
   - Result list: `ul` of Recipe Rows (below), `space-y-4`. Grid is NOT used; one column through `lg`, then `lg:grid-cols-2` with `gap-4`.
   - Footer note (12px not allowed; use 14px gray-500): "Showing top 50 of {n} recipes." only when truncated. Show top 50 initially with a "Show more recipes" outline Button (+50). Rationale: engine ranks 500 in under 100 ms, but rendering is capped for scroll performance.

## Recipe Row (ranked item) Contract

`Card` with `p-4`, tappable header region + expandable detail. Anatomy:

| Zone | Content | Style |
|------|---------|-------|
| Rank + title | Rank number (1-based, 14px/600 gray-500) then recipe name | name 16px/600 gray-900, `line-clamp-2`, `min-w-0` |
| Coverage bar | Horizontal bar, height 8px, rounded-full, track gray-100, fill `bg-primary-500` for coverage < 100, `bg-green-600` at 100 | `role="progressbar"` with `aria-valuenow`, `aria-label="{n}% of ingredients in pantry"` |
| Coverage text | "You have 6 of 8 ingredients" | 14px/400 gray-700 |
| Status pills (wrap, `gap-2`) | "Ready to cook" (green-100 bg / green-800 text, only when missing = 0); "Missing 2" (gray-100 / gray-700; red NOT used because missing is not an error); "Uses expiring: Milk (2 days left)" (amber-100 / amber-800, matches `CookFirstCard`/`RecipeCard` badge; label from `formatExpiryLabel`) | 14px/600, `rounded-full px-2 py-1` (4px vertical, no 2px values) |
| Meta | Clock + "{n} min", Users + "{n} servings" | 14px gray-500, icons 16px |
| Disclosure | Full-width 44px button "Why this ranking" / "Hide details" (`aria-expanded`, chevron) | ghost Button |
| Expanded detail | Three labelled groups (see below) | `border-t border-gray-100 pt-4 space-y-4` |
| Action | "View recipe" outline Button, opens existing `RecipeDetailModal` | no cook/deduct action (Phase 11) |

**Expanded detail groups (explainability, from engine result have / missing / expiring-used):**

1. "In your pantry" - list with `Check` icon (green-600, `aria-hidden`) + ingredient name + "need 200 g, have 350 g". Partial coverage shows "need 500 g, have 200 g (short 300 g)" and counts as missing for the pill.
2. "Using up soon" - amber text rows with expiry label. Only rendered when non-empty.
3. "Missing" - each row: ingredient name + needed quantity, and a **Substitute** button (spec below). A row for which the engine has no swap shows the button disabled-looking? NO: hide it and show nothing extra (avoid dead controls); the sheet is only offered when at least one swap exists. Engine exposes `hasSubstitute` per missing ingredient.

Ranking explanation line (14px gray-600) under group headers is not needed; the three groups plus pills are the explanation.

Sorting is fixed (engine score desc). No user-facing sort control this phase.

## Focal Points

- Main list: the top-ranked row's coverage bar plus its "Ready to cook" pill.
- Substitute sheet: the first "In your pantry" swap card.

## Substitute Affordance Contract

- **Trigger:** `Button variant="outline" size="sm"` (44px height on mobile via `size sm`), label "Find substitute", leading icon `ArrowRightLeft` 16px. Placed right-aligned on each missing-ingredient row. `aria-label="Substitute for {ingredient}"`.
- **Container:** existing `Modal` component (bottom sheet on mobile, centered `size="md"` on sm+). Title: "Substitute for {ingredient}". Not the AI modal: this is a distinct, network-free surface and must not import `AISubstitutionModal`.
- **Sheet content:**
  - Context line (14px gray-600): "Recipe needs {qty} {unit} {ingredient}."
  - Offline/source chip (14px/600, gray-100 bg, gray-700 text, `WifiOff`-free): "Built-in swaps - no internet needed". Always shown so users trust it offline; do not use a connectivity icon (connectivity status UI belongs to Phase 11).
  - List of swap cards (`ul`, `space-y-4`), ordered by engine rank (in-pantry swaps first). Each card (`rounded-lg border border-gray-200 p-4`):
    - Row 1: substitute name (16px/600) and, if the user has it: green pill "In your pantry".
    - Row 2: ratio line "Use {amount} {unit} per 1 {unit} of {ingredient}" (16px/400; ratio is pre-scaled to the recipe quantity, e.g. "Use 3/4 cup honey for 1 cup sugar").
    - Row 3: note (14px gray-600), e.g. "Reduce other liquid by 1/4 cup."
    - Row 4: dietary tags as pills (gray-100 / gray-700): "vegan", "gluten-free", etc.
  - Footer note (14px gray-500): "Swaps are general guidance. Check labels if you have allergies."
- **Diet/allergen honoring:** swaps conflicting with the user's diet or excluded ingredients are removed (not greyed out). If any were removed, show line "{n} hidden by your dietary settings" (14px gray-500, matches `DietFilterNotice` wording style; reuse that component if its props fit, else mirror its copy).
- **Interaction:** tapping a swap card does nothing destructive; there is NO "apply" in this phase (recipes are not mutated; Phase 11 owns cooking). Cards are non-interactive content, read-only. Close via the Modal X (44px), overlay tap, Escape. Focus returns to the Substitute trigger on close (Radix default).
- **Empty:** hide the trigger when no swaps exist (see above). If opened with all swaps filtered by diet: EmptyState-style inline block: heading "No safe swaps found", body "Every built-in swap conflicts with your dietary settings. Try leaving this ingredient out or buying it."

## Spacing Scale

Declared values (multiples of 4), Tailwind 4 default scale:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Pill vertical padding, icon gaps |
| sm | 8px | Pill horizontal padding, chip gaps, bar height, list inner gaps |
| md | 16px | Card padding (`p-4`), row gaps, default element spacing |
| lg | 24px | Section spacing between filter card and list on sm+ |
| xl | 32px | Layout gaps on lg |
| 2xl | 48px | Empty-state vertical padding |
| 3xl | 64px | Page-level spacing (unused on mobile) |

Exceptions: 44px minimum touch targets (`touch-target`, Button `h-11`); safe-area bottom padding via `pb-[max(1rem,env(safe-area-inset-bottom))]` inside Modal (already built in); `space-y-4` (16px) between ranked rows and swap cards uses on-scale 16px.

## Typography

Exactly 4 sizes and 2 weights for this phase (matches existing Tailwind scale in the app):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / list text / buttons | 16px (`text-base`) | 400 (semibold 600 for recipe/swap names and buttons) | 1.5 |
| Label / meta / pills / notes | 14px (`text-sm`) | 600 for pills and group headers, 400 for notes | 1.4 (Tailwind sm 20/14 = 1.43) |
| Heading (sheet title only) | 20px (`text-xl`) | 600 | 1.4 (Tailwind xl 28/20; do not override) |
| Display (page h1) | 24px (`text-2xl`) | 600 | 1.33 (Tailwind 2xl 32/24) |

Weights: 400 (regular) and 600 (`font-semibold`). Do NOT use `font-bold` (700) or `font-medium` in this phase's new components (existing pages use `font-bold` on h1; new page h1 uses 600 for the 2-weight rule). Group headers inside expanded detail use 14px/600 uppercase-free sentence case. No text below 14px.

## Color

Existing app is light-mode only (`body` forced white). Sky `primary-*` is the brand accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #ffffff | Page background, Card surfaces, Modal |
| Secondary (30%) | gray-50 `#f9fafb` / gray-100 `#f3f4f6` | Bar track, pills, inactive chips, expanded-detail dividers, swap-card borders gray-200 |
| Accent (10%) | primary-500 `#0ea5e9` (text/border variants primary-700 `#0369a1` for contrast on white) | see list below |
| Semantic positive | green-600 `#16a34a` / green-100 bg + green-800 text | "Ready to cook" pill, 100% coverage bar, "In your pantry" pill, `Check` icons |
| Semantic warning | amber-100 bg + amber-800 text (matches existing expiring badges); `--color-expiry-warning` `#f59e0b` only for icons | Expiring-used pills and rows |
| Destructive | red-500 `#ef4444` | NOT used in this phase (no destructive actions; missing is neutral gray) |

Accent (primary-500/700) reserved for: coverage bar fill when < 100%, active filter chip (`border-primary-500 bg-primary-50 text-primary-700`), focus ring (`focus-visible:ring-primary-500`), "Show more"/"Substitute"/"View recipe" outline-button hover border only if added, and the "See all you can cook" link text (primary-700). Never for pills, rank numbers, or body text.

Contrast: pill text colors listed (800 on 100) and gray-600 on white meet 4.5:1; do not use gray-400 for text (icons only).

## States

| State | Behavior |
|-------|----------|
| Loading (first query pending, no cache) | 3 skeleton Cards using `components/common/skeleton` (title bar, 8px bar, two pills). `aria-busy="true"` on the list. |
| Computing (engine run) | Engine is synchronous and under 100 ms; show no spinner. Debounce nothing; recompute with `useMemo` keyed on recipes, pantry and filters. |
| Offline with cache | Identical UI to online. No banner, no error. Results must be identical online vs offline (success criterion 3). |
| Offline with no cached data | EmptyState (see copy). |
| Stale data | Optional single line under h1 when React Query `dataUpdatedAt` is known: "Based on pantry as of {relative time}" (14px gray-500). Omit if unknown. |
| Empty pantry | EmptyState prompting add pantry items. |
| No recipes | EmptyState prompting add recipe. |
| No recipe above 0 coverage | Still list all recipes ranked (lowest coverage at bottom); show EmptyState only when zero recipes exist or filters exclude all. |
| Filters exclude all | EmptyState with "Clear filters". |
| Expanded rows | Independent per row; state kept in component only; scroll position preserved; collapse animation `transition-all duration-200`, none under `prefers-reduced-motion` (global CSS already handles). |

Interaction/accessibility: each Recipe Row header is a `button` (44px min) with `aria-expanded`/`aria-controls`; lists are `ul/li`; progress bar has text equivalent (the coverage text); Substitute trigger names the ingredient; sheet is a Radix Dialog (focus trap, Escape). Haptics: none in this phase (Phase 10). No fetch calls on any interaction in this feature.
