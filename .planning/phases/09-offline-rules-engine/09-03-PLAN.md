  <behavior>
    - Recipe needing 200 g flour with 350 g in pantry -> flour status 'have', needed 200, have 350, unit 'grams'
    - Needing 500 g, pantry 200 g -> 'partial', counts in missingCount, contributes 0.4 to coverage
    - Needing 2 cups rice, pantry 1 kg rice -> 'unitMismatch', coverage credit 1, NOT counted in missingCount, have 1 / haveUnit 'kg'
    - Needing 16 tbsp milk, pantry 1 cups milk -> 'have' (epsilon boundary)
    - Ingredient 'salt' with no pantry stock and staples containing 'salt' -> 'staple'; '3 pieces pepper' with staple 'pepper' and no stock -> 'missing' (discrete-count exception)
    - Two lines of the same canonical name in one recipe sum their need in that family
    - Ingredient quantity <= 0 or non-finite -> need unknown: 'have' if stock exists by name else 'missing'
    - coveragePercent = Math.round(100 * sum(credit) / totalCount); recipe with 0 ingredients -> coveragePercent 0, totalCount 0, sorted after all recipes with ingredients
    - expiringUsed lists used ingredients whose pantry minDaysLeft <= 7, sorted daysLeft asc then name; expiryBoost = sum of URGENCY_WEIGHTS (5/3/1)
    - score = coveragePercent + expiryBoost * EXPIRY_POINTS (4) - missingCount * MISSING_PENALTY (6)
    - Sort: readyToCook desc, then score desc, coveragePercent desc, totalTimeMinutes asc, name.toLowerCase() plain <, id plain <; rank is 1-based after sorting
    - ctx.applyDiet with restrictions ['vegetarian'] hides a recipe containing 'chicken breast' or named 'Beef stew'; hiddenByDiet counts them; applyDiet false keeps them
    - ctx.onlyReady keeps only missingCount 0; hiddenByReady counts the rest
    - ctx.hasSubstitute(canonical) sets hasSubstitute on missing matches; absent -> false
    - ctx.quantityAware false: every ingredient with stock by name is 'have' (name-level mode used by parity plan 05)
    - More than MAX_RECIPES (500) recipes -> first 500 ranked, recipesCapped true; pantry cap surfaced as pantryCapped
    - Inputs (recipes array, ingredient arrays, ctx.restrictions) unchanged after the call; same input twice -> deep-equal output
  </behavior>

Export `rankRecipes(recipes: readonly RulesRecipe[], pantry: readonly RulesPantryItem[], ctx: RulesContext): RankResult`.

    Algorithm: build the pantry index once (buildPantryIndex(pantry, ctx.today)); compile diet patterns once (compileRestrictions) only when ctx.applyDiet and restrictions non-empty; slice recipes to MAX_RECIPES. Per recipe: group ingredient lines by canonicalName (skip empty), and within a name by familyKey(resolveUnit(unit)) summing toBase(quantity). Resolve status per canonical name: staple when the name is in ctx.staples, the name has no stock, and the line is not a discrete count (count family, unitKey 'pieces'); when stock exists in a needed family compute ratio = have/need per family and take the minimum (have when ratio >= 1 - UNIT_EPSILON, partial when 0 < ratio < 1); when stock exists only in other families -> unitMismatch (Discretion choice, RESEARCH Open Question 1 / A3: present, quantity unknown; credit 1; not missing); no stock and not staple -> missing. Report needed/have in the first line's unit via fromBase (round only at display, not here); for unitMismatch report the pantry's own amount and its unit label. Diet check texts: [recipe.name, ...ingredient names]. Put the comparator in a small `compareRanked` function. Keep functions under 50 lines each and the file under 300 lines; if it grows beyond, move per-ingredient resolution into `frontend/lib/rules/match.ts` (add to SUMMARY). Use only plain `<` comparisons (no localeCompare, no Intl) so every device sorts identically. Return new frozen objects; never mutate inputs; sort a copy.
