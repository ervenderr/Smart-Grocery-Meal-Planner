## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, badge inner gap |
| sm | 8px | Gap between stacked buttons, benefit-list row gap |
| md | 16px | Card padding, sheet horizontal padding, section gap |
| lg | 24px | Gap between sheet header block and benefit list; between benefit list and CTA |
| xl | 32px | Sheet top hero spacing (icon to title) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions: all tappable controls (Buy, Restore, Maybe later, Close) are min 44px high (`Button size="md"` h-11 or `lg` h-12). Sheet bottom padding uses `max(1rem, env(safe-area-inset-bottom))` (already in Modal).

## Typography

Matches existing screens (4 sizes, 2 weights).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 | 1.5 |
| Label / helper / badge | 14px (`text-sm`) | 600 for labels, 400 for helper text | 1.5 |
| Heading | 20px (`text-xl`) | 600 | 1.2 |
| Display (price only) | 28px (`text-3xl` with `leading-9` ≈ 1.2) | 600 | 1.2 |

Weights: 400 regular + 600 semibold only. Price uses tabular figures (`tabular-nums`).
Caption text such as "Tried N times" at 12px already exists in Phase 11; do not introduce new 12px usage in this phase.

## Color

Uses existing Tailwind tokens (light theme; app has `darkMode: 'class'`, keep every pair AA-contrast in both if dark classes are present on neighbors).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | Sheet and page background |
| Secondary (30%) | `gray-50/100` (`#f9fafb` / `#f3f4f6`), borders `gray-200` | Kumaun Full card surface, benefit rows, status chip when not unlocked |
| Accent (10%) | `primary-500` `#0ea5e9` (hover `primary-600`) | See reserved list |
| Destructive | `red-800` text on `red-50` (as in Pending changes) | Conflict/failed messages only; never on Buy or upgrade sheet |

Accent reserved for: (1) the single Buy button ("Unlock Kumaun Full" / "Unlock for {price}") in the card and in the upgrade sheet, (2) the Sparkles/check icon tint in the unlocked status chip (`primary-50` bg, `primary-700` text), (3) focus rings. Restore Purchases is `secondary` or `ghost`, never accent. "Maybe later" is `ghost`.

Success state (purchased) uses `primary-50`/`primary-700` chip, not green, to stay on-brand and avoid a second accent. Errors use `red-50`/`red-800` with `AlertTriangle` icon (never color alone).

## Surfaces and Layout

### 1. Settings > "Kumaun Full" card (iOS native only)

Placement: top of Settings page, above Profile (first card), so the review path "Settings > Kumaun Full" is one scroll-free tap away. Component: `components/settings/kumaun-full-card.tsx` using `Card`, padding md (16px).

Structure (top to bottom, gap sm):
1. Row: `Sparkles` icon (20px, gray-700) + Heading "Kumaun Full" (20/600) + right-aligned status chip.
2. Body (16/400, gray-700): state-dependent description (see Copy).
3. Price line (Display 28/600, `tabular-nums`) shown only when locked and the price has loaded. Price string is `product.localizedPrice` from StoreKit verbatim. Never hardcode "$9.99" in source. Under it, helper 14/400 gray-600: "One-time purchase. No subscription."
4. Buttons (stack, full width, gap sm): `Button variant="primary" size="lg" fullWidth` Buy; `Button variant="secondary" size="md" fullWidth` Restore Purchases. When unlocked: hide Buy, keep Restore (ghost) so Apple reviewers can still find it.
5. Inline status message region (`role="status"`, `aria-live="polite"`) for restore result and errors.

Status chip variants: Free (`gray-100`/`gray-700`, "Free: 25 pantry items"), Unlocked (`primary-50`/`primary-700` with `Check` icon, "Unlocked"), Loading (skeleton bar 96x24, `animate-pulse motion-reduce:animate-none`).

### 2. Upgrade sheet (limit hit)

Trigger: only when a pantry create returns 403 `UPGRADE_REQUIRED` (or local count is already >= 25 and online check agrees) on the 26th add attempt. Never on app launch, never on scan screen open, never on expiry views. Component: `components/entitlements/upgrade-sheet.tsx` wrapping `Modal size="sm"`.

Content order (this exact frame is the Apple review screenshot, so everything below must be visible without scrolling at 1290x2796 / 1320x2868 portrait, and no debug/test chrome):
1. Title (Modal header): "Unlock Kumaun Full"
2. Lead (16/400): "You've used all 25 free pantry spots."
3. Benefit list (3 rows, `Check` icon 20px gray-700, text 16/400): "Unlimited pantry items", "More AI recipe ideas each month", "Pay once. No subscription."
4. Price block: product name "Kumaun Full" (14/600 gray-600), price in Display 28/600 from `localizedPrice`.
5. Primary: `Button primary lg fullWidth` "Unlock for {localizedPrice}".
6. Secondary: `Button secondary md fullWidth` "Restore Purchases".
7. Tertiary: `Button ghost md fullWidth` "Maybe later" (dismiss).
8. Reassurance (14/400 gray-600, centered): "Scanning, expiry reminders, recipes, meal plans and shopping lists stay free."

Behavior:
- Dismissible three ways: Close (X), "Maybe later", overlay tap / swipe-down / Escape. Dismiss returns to the Add Item form with entered data preserved (item NOT lost; show it as an unsaved draft; user may delete another item and retry).
- Never blocks: scanning, expiry alerts, viewing/editing/deleting existing items, recipes, plans, shopping remain fully usable. The sheet is not re-opened automatically in the same session after dismissal; the next add attempt re-opens it (user-initiated only).
- Price loading: if `localizedPrice` is not yet available, show skeleton in the price block and disable Buy (`aria-disabled`, label "Loading price"); Restore stays enabled. If StoreKit product fetch fails: hide price, Buy disabled, message "Couldn't load the price. Check your connection and try again." with `Try again` ghost button.
- Purchasing: Buy shows `loading` spinner, label unchanged, both other buttons disabled; Close stays enabled (purchase continues in background, result shown in Settings card).
- Success: sheet swaps to confirmation state (Check icon, title "You're all set", body "Kumaun Full is unlocked. Add as many items as you like.", button "Continue adding" primary) then retries the pending add automatically once entitlement verification returns active. Haptic success via existing `lib/native` haptics, if enabled.
- User cancels the Apple payment sheet: no error, return to idle state silently.
- Verification pending (purchase done, server verify failed/offline): message "Purchase received. We'll finish unlocking when you're back online." (`role="status"`), retry verify on reconnect; Buy hidden to prevent double purchase.

### 3. Pending changes sheet: UPGRADE_REQUIRED conflict

Reuses `PendingChangeRow` conflict classification (badge kind `conflict`, `AlertTriangle`, `red-50/red-800`). No new row component; add a mapping for the error code in the Phase 11 error-classification layer.

- Badge text: "Needs upgrade"
- Reason line (existing `row.reason`, 14px per Phase 11 style): "Your pantry is at the 25-item free limit, so this item wasn't added. Unlock Kumaun Full or free up a spot, then retry."
- Actions: `Unlock Kumaun Full` (ghost sm, opens upgrade sheet; iOS native only), `Retry change` (existing, enabled after unlock or deletion), `Discard change` (existing, existing confirmation copy "Discard this change? It won't be saved.").
- On web (no purchase UI) the "Unlock" action is replaced by the web note text in the reason: "...free up a spot, or unlock in the Kumaun iOS app, then retry."
- Row stays until the user acts; after successful unlock all `UPGRADE_REQUIRED` rows show "Retry change" prominently and the sheet offers no auto-discard.

### 4. Web fallback

No Buy, price, or Restore anywhere on web (3.1.1 and 12-CONTEXT deferred web purchase). Settings shows a small non-card note (14/400 gray-600, `Info` icon) in place of the card: "Kumaun Full is a one-time unlock in the iOS app. If you've unlocked it, signing in here keeps your unlimited pantry." Hitting the free limit on web shows an inline error (not a sheet) on the add form: "Your free pantry is full (25 items). Unlock Kumaun Full in the iOS app or remove an item to add more." No link/button to external payment. Detect native with the existing `lib/native` platform helper; Android native (if ever) behaves as web.

## Interaction and Accessibility Contract

- All controls min 44x44, visible focus ring `ring-2 ring-primary-500 ring-offset-2` (inherited from Button).
- Sheet: focus moves to title on open, returns to the triggering Add button on close; Radix Dialog handles trap. Title uses `Dialog.Title`.
- Status/result messages in `aria-live="polite"` regions; errors never rely on color only.
- Respect `prefers-reduced-motion` (spinners/skeleton use `motion-reduce:animate-none`).
- Dynamic Type: layout must hold at 200% text; benefit rows wrap, buttons grow in height, no truncation of price or CTA. Price block must remain visible via sheet scroll if it overflows at larger text, but at default text size the full sheet fits without scrolling (screenshot requirement).
- Restore Purchases flow: tap -> spinner on that button -> success "Purchase restored. Kumaun Full is unlocked." / none found "No previous purchase found for this Apple Account." / failure error copy below. Works on fresh install and after sign-in on a new device (server entitlement synced from `GET /entitlements/me`).
- Entitlement state is a UI hint only; the server decides. After a refund/revoke, Settings card reverts to the Free state with copy "Kumaun Full is no longer active on this account." and existing items remain untouched.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (sheet) | "Unlock for {localizedPrice}" (fallback while loading: "Unlock Kumaun Full", disabled) |
| Primary CTA (Settings card) | "Unlock Kumaun Full" |
| Secondary CTA | "Restore Purchases" |
| Dismiss | "Maybe later" |
| Card description (free) | "Keep everything you have. Unlock unlimited pantry items and more AI recipe ideas with a single purchase." |
| Card description (unlocked) | "Thank you. Unlimited pantry items and more AI ideas are on for this account." |
| Status chip | "Free: 25 pantry items" / "Unlocked" |
| Empty/loading state heading | Price loading: "Loading price" (skeleton, no heading) |
| Empty state body (product unavailable) | "Kumaun Full isn't available right now. Try again in a moment." + `Retry` ghost button |
| Error state: purchase failed | "The purchase didn't go through. You haven't been charged. Try again." |
| Error state: verify failed online | "We couldn't confirm your purchase yet. Tap Restore Purchases to try again." |
| Error state: verify pending offline | "Purchase received. We'll finish unlocking when you're back online." |
| Error state: restore failed | "Couldn't restore purchases. Check your connection and try again." |
| Restore success / none | "Purchase restored. Kumaun Full is unlocked." / "No previous purchase found for this Apple Account." |
| Pending changes badge + reason | "Needs upgrade" / "Your pantry is at the 25-item free limit, so this item wasn't added. Unlock Kumaun Full or free up a spot, then retry." |
| Web note | "Kumaun Full is a one-time unlock in the iOS app. If you've unlocked it, signing in here keeps your unlimited pantry." |
| Delete-account screen addition | "Deleting your account removes your Kumaun data and unlock record. Your App Store purchase belongs to your Apple Account and is not refunded or cancelled." |
| Destructive confirmation | No destructive actions are introduced in this phase. Existing "Discard change" confirmation in Pending changes is reused unchanged. |

Copy rules: never say "subscribe", "trial", "per month", or "free forever"; always "one-time" / "Pay once". No external payment links. Use "Kumaun Full" (product display name), not "Kitcha Full".
