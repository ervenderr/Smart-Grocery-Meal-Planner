- runtime.ts:
  interface OfflineRuntime {
    store: OutboxStore; persister: QueryPersister; connectivity: Connectivity; drain: DrainWorker;
    enqueue(op: NewOp, opts?: { idempotencyKey?: string; resolved?: unknown }): Promise<OutboxOp | null>   // store.enqueue(currentUserId, op, opts) then drain.kick('enqueue'); throws when no user
    refreshFromServer(reason: string): Promise<'ok' | 'offline' | 'skipped' | 'error'>  // single-flight; fetchBootstrapSnapshot + applySnapshot with reapply over current pending ops
    onEvent(listener: (e: DrainEvent) => void): () => void   // UI toasts/haptics subscribe (11-13)
    registerExecutors(extra: Partial<Record<OpKind, Executor>>): void  // extension point; 11-14 adds finish/cook to the default registry directly
    applyWrites(writes: CacheWrites): void
    dispose(): void
  }
  createOfflineRuntime({ db, queryClient, getUserId, transportClient, probe, now? }): OfflineRuntime
  getOfflineRuntime(): OfflineRuntime | null ; setOfflineRuntime(r | null) (boot sets it)
  Event handling: applied -> applyWrites(applyResult(op, result)); parked -> no cache change (the change stays visible with a failed marker; the UI announces it and rollback happens on discard via 11-12 actions); finished with applied > 0 and no queued ops -> refreshFromServer('drained').
- boot.ts:
  BOOT_TIMEOUT_MS = 1500
  type BootResult = { status: 'disabled' } | { status: 'no-user' } | { status: 'ready'; restored: number } | { status: 'empty-offline' } | { status: 'failed-open'; reason: string }
  bootOffline({ queryClient, getDb, getUserId, waitForAuth, createRuntime, timeoutMs? }): Promise<BootResult>
  Steps: if !enabled -> disabled; await waitForAuth (bounded); db = await getDb() (null -> failed-open); migrate; store.resetInFlight(); userId null -> no-user (runtime still created so login later works); persister.hydrateAll(); fold pending ops over hydrated canonical keys via reapplyForKey; persister.start(); queryClient.setDefaultOptions({ queries: { networkMode: 'offlineFirst', retry: (n, e) => !isOfflineError(e) && n < 1 } }) on native only; registerOfflineGate; setOfflineRuntime; restored 0 and not reachable -> empty-offline; else ready. Whole sequence raced against timeoutMs -> failed-open (work continues in background, gate opens).
- triggers.ts: attachTriggers(runtime, { loadApp, attachNetwork }): Promise<() => void>  (App active -> drain.kick('foreground') + refreshFromServer('foreground'); App inactive -> persister.flush(); connectivity offline->online transition -> drain.kick('online') + refreshFromServer('online'))
- offline-boot-gate.tsx: OfflineBootGate({ children }) -> renders null until bootOffline settles (when enabled), then children; on 'empty-offline' renders FirstLaunchOffline whose Try again calls runtime.refreshFromServer('retry') and re-renders children on 'ok'
- first-launch-offline.tsx: full-page EmptyState, icon WifiOff, heading 'Connect once to get started', body 'Kitcha needs an internet connection the first time to download your data.', action 'Try again' (UI-SPEC section 6)
