Contracts THIS plan creates:
- session-hooks.ts (no imports from runtime, so auth-store stays light): type SessionEndIntent = 'expired' | 'logout' | 'deleted'; registerSessionHandlers({ beforeClear: () => void; afterClear: () => void } | null); notifySessionClearing(); notifySessionCleared(); setSessionEndIntent(i); consumeSessionEndIntent(): SessionEndIntent (defaults to 'expired' when unset: the safe, data-keeping choice)
- user-scope.ts: type TransitionAction = { type: 'wipe-cache' } | { type: 'delete-user-ops'; userId: string } | { type: 'pause-user-ops'; userId: string } | { type: 'set-meta-user'; userId: string | null } | { type: 'hydrate' } | { type: 'resume-user-ops'; userId: string } | { type: 'refresh' }; planUserTransition({ prevUserId, nextUserId, metaUserId, intent }): TransitionAction[]
  Rules: sign-out with intent expired -> [pause-user-ops(prev)] (cache kept); logout -> [pause-user-ops(prev), wipe-cache, set-meta-user(null)]; deleted -> [delete-user-ops(prev), wipe-cache, set-meta-user(null)]; sign-in where next === metaUserId -> [hydrate, resume-user-ops(next), refresh]; sign-in where metaUserId is null -> [set-meta-user(next), resume-user-ops(next), refresh]; sign-in where next !== metaUserId (non-null) -> [wipe-cache, set-meta-user(next), resume-user-ops(next), refresh] (previous user's ops untouched); boot uses the same function with prevUserId = null
- apply-transition.ts: applyUserTransition(runtime, queryClient, db, actions): Promise<void> executes actions in order (hydrate also folds pending ops via reapplyForKey; refresh calls runtime.refreshFromServer('login'))
- runtime.ts: registers session handlers (beforeClear -> persister.suspend(); afterClear -> keep suspended until the transition is applied, then persister.resume()) and subscribes to useAuthStore user id changes, computing intent via consumeSessionEndIntent on sign-out
- boot.ts: replaces its inline user check with planUserTransition at boot
</interfaces>
