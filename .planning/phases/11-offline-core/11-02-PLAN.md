<objective>
Additive backend change (decided and flagged per the orchestrator brief, RESEARCH Open Question 2 / Pattern 7): accept an optional `occurredAt` on `POST /cook/apply` so a queued offline "Cooked it" or meal-plan "mark as cooked" records the time the user tapped it, not the sync time.

Purpose: Without it, meals cooked offline show the reconnect date as "Cooked {date}" in the meal plan. The change is tiny, reuses the existing `clampOccurredAt`, and is safe for old clients.
Output: validation chain, controller pass-through, service use of the clamped time, Jest tests. NOT deployed (CONTEXT: "Do not push backend deploys").

Decision record for the SUMMARY (flag to user): backend additive change = optional `occurredAt` on `cook/apply` only. No other backend change in Phase 11. OFF-07 "mark" is the queued cook op (no new mark endpoint). Web IndexedDB fallback is skipped.
