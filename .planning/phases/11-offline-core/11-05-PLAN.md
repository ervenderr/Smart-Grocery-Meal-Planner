<feature>
  <name>Outbox core state machine</name>
  <files>frontend/lib/offline/outbox/*</files>
  <behavior>
    - NewOpSchema rejects pantry.update with a quantity key, adjust delta 0 or 0.001, non-uuid ids, empty labels
    - classify: network -> retry countsAttempt false; timeout -> retry countsAttempt false; 503 -> retry countsAttempt true; 503 at attempts 7 -> park max-attempts; 429 with retryAfterMs 5000 -> retry retryAfterMs 5000; 409 IDEMPOTENCY_IN_FLIGHT -> retry; 409 ALREADY_COOKED -> park conflict code ALREADY_COOKED; 404 on shopping.item.delete -> ok; 404 on pantry.adjust -> park gone; 410 -> park gone; 400 and 422 -> park invalid; 422 IDEMPOTENCY_KEY_REUSED -> park invalid with code; 401 -> pause-auth
    - backoff: attempts 0 within [800,1200]; attempts 10 never exceeds 36000; retryAfterMs 5000 at attempts 0 returns at least 5000
    - coalesce: update after un-attempted update merges fields LWW; update after attempted update inserts; adjust +2 then +3 (un-attempted) merges to +5; +0.1 then +0.2 merges to 0.3 exactly; +2 then -2 drops both; update after un-attempted create merges into create item; delete after un-attempted create drops all and inserts nothing; delete after attempted create drops un-attempted updates and inserts delete
    - fold: shopping create/update/delete/check applied in seq order; pantry adjust clamps at 0; pantry delete removes; meal plan cook op sets cookedAt; failed and blocked ops ARE still folded (a parked change stays visible with a failed marker until the user discards it, UI-SPEC section 5; rollback happens on discard)
    - store: enqueue persists all fields; enqueue with opts.idempotencyKey and opts.resolved stores both verbatim and is never merged into; two enqueues for different entities keep seq order; nextReady skips entity with earlier failed op but returns other entity; finish not ready while an earlier shopping-item op is queued; park blocks dependents and retry unblocks; discard returns op + dependents; resetInFlight moves in_flight to queued; pauseAuth/resumeAuth round-trip keeps all rows; saveResolved does not overwrite; subscribe fires after enqueue and complete; enqueue with invalid op rejects without writing
    - durability: a store rebuilt over the same node:sqlite file after closing returns identical rows (simulated kill)
  </behavior>
  <implementation>Decimal-safe adjust: round(a*100 + b*100)/100 on integers. Never mutate inputs; every merge produces new objects. Files under 250 lines, functions under 50 lines.</implementation>
</feature>
