Purpose: Every later plan (cache persister, outbox, barcode cache) is built and tested against this seam (RESEARCH Pattern 1). The schema must protect unsynced user work from day one (RESEARCH Runtime State Inventory: cache tables may be wiped, the outbox only migrates forward).

Decision ID mapping used by every Phase 11 plan (11-CONTEXT.md lists decisions as bullets without IDs; numbered here in document order): D-01 Reads (SQLite-persisted React Query cache, hydrate before first render, bootstrap paging, versioned cache schema); D-02 Writes (custom persisted outbox, single sequential drain, backoff, triggers, short timeouts); D-03 Optimistic UI (immediate apply, reconcile, rollback + message); D-04 Offline-capable ops list (and the online-only list); D-05 Conflict policy (LWW per field, delete wins, deltas sum and clamp, error codes mapped, failed ops parked with retry/discard); D-06 Status UI (indicator + Pending changes sheet); D-07 Durability (survive kill and reboot, exactly-once, automated kill/relaunch + flaky-server tests); D-08 Web keeps working (feature-detected, build unchanged); D-09 Auth offline (no logout on token expiry, refresh on reconnect, never wipe the outbox on 401).

frontend/lib/offline/sql/types.ts
- interface SqlRunResult { changes: number; lastInsertRowid?: number }
- interface SqlDb {
    exec(sql: string): Promise<void>;
    run(sql: string, params?: readonly unknown[]): Promise<SqlRunResult>;
    query<T>(sql: string, params?: readonly unknown[]): Promise<T[]>;
    transaction<T>(fn: (tx: SqlDb) => Promise<T>): Promise<T>;
  }
  Params are positional `?` only. No string-built SQL with user data anywhere in lib/offline.

frontend/lib/offline/sql/migrations.ts
- interface MigrationResult { cacheFrom: number | null; cacheTo: number; outboxFrom: number | null; outboxTo: number; cacheWiped: boolean }
- migrate(db: SqlDb, versions?: { cache: number; outbox: number }): Promise<MigrationResult>
  Runs inside db.transaction. Cache tables (cache_meta, cache_entries, barcode_cache) are dropped and recreated when stored cache version != target. pending_scan holds unsynced scan state and is treated like the outbox (never dropped). Outbox and pending_scan: CREATE IF NOT EXISTS, then apply ordered forward steps from OUTBOX_MIGRATIONS (array indexed by version; v1 is the base DDL). A stored outbox version GREATER than the target throws OutboxDowngradeError (never drop user work on app downgrade).
- class OutboxDowngradeError extends Error

frontend/lib/offline/sql/node-sqldb.test-helper.ts (tests only; filename deliberately does not match the vitest include glob and is never imported by app code)
- createNodeSqlDb(path?: string): SqlDb & { close(): void }  -- wraps `DatabaseSync` from 'node:sqlite'; transaction uses BEGIN/COMMIT/ROLLBACK with nested-call protection (a nested transaction call reuses the outer tx)

- UUID_V4_RE (same shape express-validator isUUID(4) accepts)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app code -> local SQLite | Strings from user input (item names) and server payloads are written to the on-device DB |
| app version N -> N-1 (downgrade) | Older binary opening a newer DB could destroy unsynced work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | SqlDb.run/query | mitigate | Positional `?` parameters only; DDL constants are module-level literals; acceptance grep for no template-literal SQL with variables in later plans |
| T-11-02 | Denial of Service | migrate() | mitigate | Single transaction; OutboxDowngradeError aborts without writes; cache wipe never touches outbox/pending_scan (tested) |
| T-11-03 | Spoofing | newId() | mitigate | IDs from crypto.randomUUID or crypto.getRandomValues only; no Math.random (grep gate) |
</threat_model>
