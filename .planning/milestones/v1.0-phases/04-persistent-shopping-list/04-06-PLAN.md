## Phase Goal

**As a** Kitcha user shopping with my phone, **I want to** keep one saved shopping list that I can build by hand or from a meal plan, tick off in the aisle and close with what I actually spent, **so that** I buy what I need without losing the list or overspending.

Purpose: SHOP-03 (generate a list from a meal plan; it is saved). No pantry subtraction or unit conversion (Phase 5).
Output: aggregate + merge pure modules with unit tests, generate service/endpoint with integration tests.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-23 | Information disclosure (IDOR) | mealPlanId | mitigate | Reuse `generateShoppingList` scoped `findFirst({ id, userId, deletedAt: null })`; 404 MEAL_PLAN_NOT_FOUND for foreign/unknown; cross-user test |
| T-04-24 | Tampering | merge updates | mitigate | Update ids come only from items loaded from the locked active list of this user |
| T-04-25 | Denial of service | huge plans / bad recipe data | mitigate | Cap check before writes (300), names truncated to 100, quantities clamped to 0.01..99999, non-finite skipped |
| T-04-26 | Tampering (race) | concurrent generate from two devices | mitigate | Single transaction holding `FOR UPDATE` on the list row; merge computed inside the lock |
