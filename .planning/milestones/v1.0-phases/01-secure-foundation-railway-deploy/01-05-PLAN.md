    Per the CONTEXT decision "End-to-end production smoke test after deploy: register, login, pantry create/read/update/delete against the Railway URL":
    Create scripts/smoke-prod.sh (bash, `set -euo pipefail`, executable). Inputs: API (required, e.g. https://x.up.railway.app, no trailing slash) and FE (optional, default https://kitcha-ai.vercel.app). A flag `--api-only` skips the frontend bundle check. It needs curl and jq, prints PASS/FAIL per check, exits non-zero on the first failure, and never prints the JWT. Checks, in this order:
    (1) GET $API/health returns 200 with status ok.
    (2) Preflight OPTIONS $API/api/v1/auth/login with Origin $FE, Access-Control-Request-Method POST and Access-Control-Request-Headers authorization,content-type returns 200, and access-control-allow-origin equals $FE.
    (3) Preview origin preflight with Origin https://kitcha-git-main-ervenderrs-projects.vercel.app is allowed.
    (4) GET $API/api/v1 with Origin https://evil.example returns 403 and JSON message "Origin not allowed".
    (5) Rate-limit identity: two GET $API/api/v1 with X-Forwarded-For "1.1.1.1" and then "2.2.2.2" (Railway appends the real IP). The ratelimit-remaining of the second is exactly 1 lower than the first.
    (6) Signup with a unique smoke+<epoch>@example.com and a generated compliant password (e.g. "Smoke" + epoch + "Aa1"), expecting 201 and a token. Then login, expecting 200 and a token. Do not do any deliberate failed-login checks (they would burn authLimiter).
    (7) Pantry CRUD with Authorization: Bearer: POST returns 201 and an id; GET returns 200; PATCH {quantity: 3} returns 200; DELETE returns 200; GET returns 404.
    (8) Unless --api-only: fetch $FE, extract the /_next/static/...js URLs from the HTML, download them, and assert at least one contains the API host and none contains "localhost:3001".
    Print a final summary and note that the smoke user remains in the DB (no delete-account endpoint). Then run `bash -n scripts/smoke-prod.sh` and run it once with `API=https://kitcha-smoke-placeholder.invalid scripts/smoke-prod.sh --api-only`, confirming it FAILS at check 1 (RED).
  </action>
