## Phase Goal

ROADMAP goal (verbatim; ROADMAP has no user-story line for this phase): The pantry stays accurate with minimal typing as users scan, shop and cook.

<objective>
Vertical slice for CAP-05 quantity quick edit: a user standing in the kitchen taps +/- on a pantry card (or types a number) and the pantry updates, down to a "Used up" state at 0 that can be removed with Undo. Backend PATCH is relaxed to allow 0 (per CONTEXT "Quantity never below 0; 0 shows a used up state"), the pantry page moves to React Query for optimistic updates (resolved decision), and a reusable QuantityStepper is created.

Purpose: CAP-05 (quantity half). The expiry half ships in 06-05 on top of the `onPatch` card contract created here.
Output: relaxed PATCH with tests, pure quantity helpers with Vitest, pantry hooks, stepper, used-up badge, migrated page and card.
</objective>

- `frontend/components/pantry/quantity-stepper.tsx`: controlled, generic `QuantityStepper({ value, unitLabel, step, min = 0, max = 99999, label, onChange, disabled })` (label is the item name used in aria-labels). No data fetching inside.
- Card props after this plan: `{ item, onEdit, onDelete, onPatch: (item: PantryItem, patch: PantryQuickPatch) => Promise<void>, onRemoveUsedUp: (item: PantryItem) => void }`. onPatch resolves on success and rejects after the optimistic rollback on error (06-05's expiry sheet awaits it to stay open on failure).
