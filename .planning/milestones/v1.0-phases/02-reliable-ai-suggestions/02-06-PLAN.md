## Phase Goal

**As a** Kitcha user planning meals on my phone, **I want to** get recipe, meal-plan and substitution suggestions and product lookups that are always well-formed, respect my diet, and tell me clearly when AI is unavailable or I hit my daily limit, **so that** I can trust the suggestions without errors and without the app costing money.

<objective>
Slice (UI): users see clear server messages in AI modals, see when diet filtering hid items, and can look up a product by barcode number in the Add Pantry Item modal with visible attribution (per CONTEXT: frontend error contract, reusable attribution component, minimal barcode-number lookup; camera scanning stays in Phase 6).

Output: error helper, updated AI modals and types, food API client, FoodDataAttribution and BarcodeLookup components, pantry modal integration. Frontend has no test runner: verification is lint + type-check + production build (CI gates). Frontend deploys via push to main (Vercel) in plan 02-07.
</objective>

- GET /api/v1/food/nutrition?query= -> `{results: {fdcId, description, dataType, nutritionPer100g}[], attribution, cached}`
